# 部署与安全

## HTTPS

中心可以直接加载证书：

```bash
bun run hub --host 0.0.0.0 --port 19200 \
  --public-url https://hub.example.com:19200 \
  --cert /path/to/fullchain.pem --key /path/to/privkey.pem
```

证书需要被浏览器和节点的操作系统信任。IP 地址访问同样需要匹配该 IP 的证书。

也可以让反向代理提供 HTTPS，并把中心保持在回环地址：

```bash
bun run hub --public-url https://hub.example.com
```

反向代理需要保留外部 Host，并支持整个站点的 WebSocket Upgrade、流式响应和较大的附件请求体。节点连接和独立传输通道也使用 WebSocket，通知事件流 `/_hub/notifications/events` 需要关闭代理缓冲。原生页面路由依赖同源 Referer，请保留该请求头。

原生操作接口可能等待完整推理或人工审批后才返回 HTTP 响应头。hub 不对这类长操作设置固定的响应头期限，普通资源仍保留 30 秒期限。反向代理的上游等待期限也需覆盖任务和审批等待，例如配置相应的 `proxy_read_timeout`。聊天 WebSocket 有活动，不会自动延长另一个 HTTP 请求的期限。

出现超时或连接中断时，先检查原会话是否仍在运行，不要重复发送。关闭等待连接不代表任务已停止，需要停止时使用会话中的停止操作。

## 安全边界

- 当前版本是**单用户系统**，所有设备属于同一信任域。中心密码允许访问全部已注册设备。
- 中心能读取经它转发的会话和文件。审批命令、路径以及输入回答也会经过中心。会话摘要、交互、完成通知与后端日志只保存在内存，任务回复正文仅按需转发到浏览器，计划定义、任务描述、运行状态和错误摘要另存 SQLite。HTTPS 是分段传输加密，不是设备与浏览器之间的端到端加密。
- 设备 GUI 与管理界面共享浏览器来源。只运行自己信任的后端程序，不能作为不可信用户或设备之间的隔离方案。后端日志可能包含敏感内容，只在已登录界面展示，不持久保存。
- 节点凭据仅允许连接所属设备，不能用作浏览器登录或访问浏览器 SSE 接口。节点接收跨设备完成摘要必须同时满足本机开启和已登录浏览器的显式授权；绑定可随时撤销。中心只保存凭据散列。
- 登录 Cookie 使用 HttpOnly、SameSite=Strict，HTTPS 入口增加 Secure。登录会话保存在内存中，有效期 12 小时，中心重启后需要重新登录。
- 中心 Cookie、节点认证头不会传给本机 o-pi。
- 设备操作不会自动重试。连接在提交后中断时，请先检查会话状态，避免重复操作。
- `data/` 和 `node.json` 都是敏感数据，需限制读取权限并妥善备份。任务描述和错误摘要也可能包含秘密。备份时先正常停止中心，再复制整个数据目录，不要运行中只复制 SQLite 主文件。

## 传输压缩与静态资源缓存

- 节点到中心的数据通道、中心到浏览器的 WebSocket 会协商逐帧压缩，不支持压缩的旧端仍可连接。压缩字典不跨消息复用，消息大小限制按解压后的内容计算。
- 原生会话快照等数据消息上限为 64 MiB，节点控制消息仍为 16 MiB。限制针对单条消息，不是会话文件总大小。超过数据上限仍会断开连接，不截断历史或自动重发操作。中心和对应节点都需更新并重启，才能打开超过旧 16 MiB 限额的快照。
- 原生页面 `/assets/` 下带内容哈希的 JS/CSS 资源支持 gzip，并允许浏览器私有缓存一年。缓存按设备 URL、登录 Cookie 和压缩格式区分，退出登录后不会复用上一登录的资源响应。中心不持久保存资源副本。
- HTML、API、聊天数据、未带哈希的资源、带查询参数的资源、错误响应和 Range 下载均保持 `no-store`。文件下载和 Range 的字节语义不变。
- 建议先更新并重启中心，再等任务结束后更新并重启节点。仅更新中心时，浏览器侧压缩和缓存即可生效，但旧节点的数据通道不会自动启用压缩。重新打开页面后，第一次请求填充缓存，后续访问可复用。

这些优化减少传输量，不改变原生页面的渲染方式，不能消除 o-pi 本身处理大型会话时的主线程卡顿。
