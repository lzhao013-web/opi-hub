# 架构

## 运行边界

```text
浏览器 ── HTTP / WebSocket ── 中心
                              ↑
                      节点主动出站连接
                              │
                  节点创建并持有的 opi-web 子进程
```

中心和节点使用 Node.js 24。Bun 仅作为安装和构建工具，避免当前环境中 Bun 的 Node HTTP 流式响应兼容问题。

- `src/hub/`：单用户认证、设备持久化、在线连接、转发和计划任务。
- `src/hub/scheduling/`：时区计算、SQLite 计划与运行记录、触发和状态核对。
- `src/node/`：托管子进程、生命周期和 SDK 订阅归属、中心连接恢复、HTTP 与 WebSocket 转发、可选的本机系统通知。
- `src/adapters/opi/`：o-pi 协议校验、目录增量、独立会话订阅和交互操作，不导入 o-pi 源码。
- `src/shared/`：传输消息、校验、头字段白名单和背压。
- `src/web/`：无框架管理界面及原生页面入口适配。

UI 参考 o-pi 的浅灰/炭灰表面、`#007AFF` 主色、系统字体、弱分隔线和圆角。原生聊天界面由设备端提供，中心不重新实现。

## 连接与身份

设备 ID 在注册时生成，与 IP 无关。设备使用 `id.secret` 凭据连接 `/_hub/connect`，中心保存 secret 的 SHA-256 散列。浏览器使用独立的会话 Cookie。

节点每 15 秒检查本机 `/health` 并报告服务状态。中心通过 WebSocket ping/pong 检测失联。节点在线和本机 Web 就绪是两个不同状态。

每个转发请求都有独立的一次性请求 ID。中心通过控制连接下发请求，节点主动连接 `/_hub/stream/<id>` 承载数据。中心验证请求 ID 所属设备和当前控制连接，拒绝跨设备或已消费的通道。

这比所有文件复用一个数据连接多一些握手，但可以使用传输层背压隔离慢下载，不需要自行实现多路复用的流量窗口。

节点的数据通道和浏览器 WebSocket 协商 `permessage-deflate`，两端均要求不跨消息复用压缩字典，采用压缩级别 3、1 KiB 阈值和最多 4 个并发压缩操作。节点控制连接不协商压缩，节点到本机后端的回环 WebSocket 仍不压缩。未协商成功的旧端继续使用原有未压缩帧，无需改变消息协议。

控制连接单条消息上限保持 16 MiB。浏览器、节点数据通道和本机 o-pi 订阅的单条消息上限统一为 64 MiB，按解压后的完整消息计算，不限制会话文件总大小。转发队列与握手前缓存各最多积压 128 MiB，发送回调与暂停读取继续传播背压。超限会断开连接，不截断消息、不重放操作。中心与节点均需更新并重启，旧端仍受原 16 MiB 限额约束。

## HTTP

请求元数据通过控制连接发送，包含方法、相对路径和头字段白名单。请求体和响应体通过二进制 WebSocket 帧流式传递，以文本控制帧表示响应头和结束。

本机 Host 和 Origin 根据当前托管进程的回环地址重建。中心 Cookie 和 Authorization 不下传。响应采用头字段白名单，不接受目标设置中心 Cookie。

普通文件不聚合到内存，支持 Range。只有原生 HTML 入口在 2 MiB 上限内缓冲以注入脚本。数据连接建立和 HTTP 通道就绪各有 10 秒期限。请求体转发完毕后，普通资源的响应头等待期限为 30 秒。

只有无查询参数、无 Range 的原生 `/assets/<名称>-<至少八位哈希>.js` 或 `.css` 的 GET/HEAD 请求可进入静态资源缓存流程。200 响应还须有对应 JavaScript/CSS 媒体类型，条件请求的 304 只更新已有表示的元数据。中心设置 `Cache-Control: private, max-age=31536000, immutable` 和 `Vary: Cookie, Accept-Encoding`，设备由 URL 隔离。缓存只在浏览器中保存代码资源，不在中心新增缓存文件。内容变化必须使用新的哈希文件名。HTML、API、聊天数据、错误响应及其他路径保持 `no-store`。

仅这类静态资源可转发 `If-None-Match` 和 `If-Modified-Since`。浏览器接受 gzip 时，中心对成功的 GET 响应使用流式 gzip，不依赖本机后端压缩，也不把文件整包读入内存。压缩表示移除原 Content-Length，并将强 ETag 改为弱 ETag。HEAD 和 304 不生成响应体。压缩流的背压继续传给节点，浏览器中断或退出登录会销毁压缩流并回收通道，正文发送前发生错误会清除缓存与压缩元数据再返回 `no-store` 错误响应。

原生 `POST /api/action` 和 `POST /api/query` 可能等待完整推理、命令、压缩、登录或审批流程，不能使用普通资源的响应头期限。通道就绪后不再设置这类请求的固定响应头期限，进度仍走独立 WebSocket。浏览器断开、退出登录或节点失联会回收转发连接，不自动重发任务，也不能据此认定原生操作已取消。

节点适配器访问所属回环 HTTP 后端时使用原生 `http.request`，连接期限为 10 秒，不使用 `fetch` 隐含的 5 分钟响应头期限。调用方的取消信号、查询期限和计划任务超时保持有效，客户端关闭会中断自己的在途等待。API 错误保留状态与 Unicode 内容，不自动重试或跟随重定向。

## 原生 GUI 适配

每个设备入口为 `/n/<id>/`，不依赖通配域名或独立端口。

- HTML 中的根路径资源属性增加设备前缀。相对路径资源保留原样。
- 入口脚本适配原生 `/api/` WebSocket URL，并按设备区分 `opi.session` 存储键。
- `hub-session` 查询参数直接指定运行会话。`hub-path` 先以未选择会话的客户端握手，再调用 `openSession`，不短暂展示默认会话。打开失败在原生页显示错误。
- 原生 HTTP API 和文件资源的根路径请求，根据同源 Referer 中的设备路径路由。
- 转发页面设置 `Referrer-Policy: same-origin`，不把完整设备路径发送到外站。
- 不使用全浏览器共享的“当前设备”Cookie，不改写用户消息或 API 响应正文。

所有节点属于同一个可信用户。此同源方案不提供不可信设备间的浏览器隔离。

## 管理协议

节点端保持一个管理客户端，订阅 `activity` 和 `workspaces` 元数据，不再主动请求全量 `sessions`，也不保留上游主动附带的历史。两种已支持的帧按各自 ACK 格式确认，增量严格检查基线和区间。

`/_hub/history` 只在用户加载工作区历史或提交历史查询时调用。请求通过 `history` 控制消息到目标节点，节点创建独立、未选择会话的临时客户端。带类型封装的协议显式请求 `all: true`，无类型封装二进制使用原有全目录刷新。接口粒度是单台后端目录，页面再按工作区筛选，不能声称实现了上游的逐工作区扫描。

查询完成后以事件连接的 ping/pong 同步已排队的目录帧，随后释放临时客户端。历史只作为请求结果返回，不并入持续管理状态。中心每设备只允许一个在途历史查询，35 秒超时，节点 30 秒超时。取消、退出登录或断线会发送 `cancelHistory` 并关闭临时订阅，但无法撤销上游已经开始的文件扫描。

页面历史缓存绑定设备连接及托管实例代数，断线、连接替换或管理订阅失败时清除，旧请求不得回填新连接的数据。页面通过会话文件身份合并历史与运行记录，防止打开历史后出现两条记录。

目录客户端观察启动会话，以接收尚未进入运行目录的启动交互。其他运行中或等待中的会话各有独立订阅。节点也只读观察原生转发连接中的 `selected` 事件，订阅这些浏览器已经打开的会话，以发现未公开到全局目录的新建空白会话。发现提示不修改数据，也不替浏览器发送 ACK。已有待处理交互的订阅在页面关闭后保留到交互结束。

订阅不会改变浏览器导航，空闲历史不会为了获取列表而全部加载执行实例。观察启动会话会保留该实例。仅在本机直接创建、既不在目录也未经过 hub 的空白会话无法通过现有协议发现，完整覆盖需要额外接口或扩展。

会话摘要、归一化交互、完成通知元数据和计划回复定位标识通过控制连接的 `management` 消息上报中心，不上报聊天正文。中心 `/_hub/overview` 组合设备、工作区元数据、运行会话和交互，不包括历史目录。首页只显示正在进行的会话及最多 5 个空闲实例，历史有独立的显式查询入口。中心状态在连接断开时立即失效。节点端的本机订阅与节点进程同生命周期，中心暂时断线不会丢失已发现的未落盘交互，重连后上报当前快照。节点进程本身重启后，仍只能从目录、启动会话和新的浏览器连接重新发现会话。

回答通过 `respond` 控制请求交给对应节点，节点仍调用原生 `dialog` 操作。关联 ID 必须属于当前设备连接；同一交互的并发提交被阻止。中心 30 秒超时不重试，节点请求 25 秒超时。回答进行中保留订阅，避免交互完成时回收订阅并中断它自己的 HTTP 响应。

普通输入、密钥输入、编辑器、确认、选择和结构化命令审批分别保留原始值及选项，不把所有 waiting 状态都当作工具授权。源协议不匹配时明确报告错误，不使用旧摘要伪装在线状态。

## 消息中心与完成通知

管理界面保留同一个入口，但待处理交互和完成通知分区、独立计数。已读操作只修改通知状态，不调用原生审批接口。

`CompletionObserver` 复用不保留正文的 `ExecutionState`，观察实际运行、忙碌标记及新助手条目的停止原因。只有正常结束或长度上限结束产生普通完成事实。初始历史、重复快照、重连、取消、错误和纯 Shell 不产生完成提醒。目录订阅、运行会话订阅及原生转发观察按会话和回复条目标识去重。计划任务以 `AgentTask` 的完成记录为准，不依赖订阅是否赶上很短的执行，也不依赖上游可能被其他前台窗口抑制的原生通知。

节点快照保留最近 100 条完成元数据。中心的 `NotificationCenter` 跨设备合并最近 100 条，并在内存维护已读、每浏览器投递认领和来源快照。来源快照防止已淘汰通知在节点重放时重新进入列表。每条节点控制连接的首份 ready 快照只恢复完成记录，不补弹其中的旧通知；保留来源快照索引，避免重连时让已淘汰的记录重新进入列表。

`/_hub/notifications/events` 是认证 SSE 连接，页面隐藏后仍接收通知，每 15 秒发送心跳。登录失效、退出或中心关闭会释放连接。慢客户端积压超过传输上限时断开，由 EventSource 重连。反向代理需允许事件流及时发送，不应缓冲该路径。

原生入口脚本通过 `BroadcastChannel` 上报当前浏览器的会话查看提示，并向认证的 `/_hub/notifications/presence` 接口提交带序号的查看状态。每 5 秒续期，中心按 15 秒租约记录，在收到完成事实时绑定被抑制的浏览器，避免延迟投递时误弹。查看提示有独立页面身份，不把独立管理连接和结果读取连接算作用户查看。会话与设备同时匹配才抑制，其他会话在前台不影响通知。

同一浏览器用非凭据的随机接收端标识认领通知，中心原子拒绝重复认领。通知权限只由用户显式授权。系统弹窗仅含设备与会话标题，正文不进入通知。Hub 活跃时入口脚本拦截原生完成弹窗投递，由消息中心统一提醒。不提供 Web Push。

### 节点通知下行

接收节点默认检测本机系统通知入口，未配置或配置 `notifications: true` 且入口可用时，通过现有控制 WebSocket 发送 `subscribeNotifications`。`NodeNotifications` 只向主动订阅、当前连接有效且具有持久化 `notificationDestination` 绑定的节点下发 `completionNotification`；不会向旧节点、配置 `notifications: false` 或通知入口不可用的节点发送新控制消息。节点凭据不能调用浏览器 SSE。

绑定由已登录用户在 `POST /_hub/notifications/receiver` 提交，校验同源、目标设备存在及随机接收端标识。`Store.bindNotifications` 原子保存到 `hub.json`，保证一个浏览器配置只绑定一个节点、一个节点关联一个浏览器配置。网页不能代替节点修改本机开关、通知程序或启动命令。节点开关或浏览器授权缺一不可，拥有执行节点凭据本身不等于可以订阅全部设备元数据。

中心仅将新完成事件投递到控制连接，不发送历史快照；节点优先使用所绑定浏览器的标识调用同一个原子 `claim`，然后才发布浏览器 SSE 快照。因此两个渠道不会同时投递同一接收端的系统提醒，原有前台查看租约也可抑制节点弹窗。查看提示响应返回接收节点是否正在订阅，原生入口脚本按序号维护 12 秒租约，在 Hub 页面全部关闭后仍避免重复弹出原生通知。接收节点离线或未订阅时不抢占认领，后续新事件可由浏览器投递；已投递失败的事件不自动重试。

默认的完成通知下行负载只包含有界的通知标识、来源设备标识与名称、会话标题和完成时间，不包含回复、工作目录、文件路径或中心凭据。`LocalNotifications` 在节点进程内维护最近 100 个标识和最多 32 条串行待发送队列，重连不清空去重集合，退出时取消自己的通知子进程和待发条目。系统命令由本机平台适配器固定选择，使用 `execFile`、`shell: false` 和 `windowsHide: true`，中心文本只进入参数或标准输入，不拼接脚本。协议、队列和命令构造用无桌面测试验证，不自动弹出真实系统通知；各平台的真实权限与弹窗显示仍需在对应桌面环境验收。

中心通过订阅状态声明支持完成通知链接。接收节点用本机配置的 Hub 地址和通知标识构造链接，不增加完成通知负载，也不读取文件路径。Hub 登录后从现有通知列表定位会话或运行结果。新打开的标签页通过同源 `BroadcastChannel` 查找正在查看同一设备、同一会话的原生页，或可显示计划结果的 Hub 页。目标页确认取得焦点后才尝试关闭中转页。无匹配页或焦点请求未成功时，当前标签页继续显示结果。Windows 使用系统协议激活打开浏览器。Linux 通过 `notify-send` 回传查看动作，再用 `xdg-open` 打开浏览器。完成通知的点击等待最多八条，单条约两分钟，不占用普通通知队列或审批等待额度。额度用完时仍发普通提醒。

Windows 节点显式启用 `--windows-focus` 时，普通完成通知的消息外层另带标签定位标记。中心用进程内随机密钥和 HMAC 区分浏览器接收端、设备及会话，不向节点发送文件路径。原生页从查看状态响应取得同一标记，把它置于查询参数首位。切换或断开会话时立即移除旧标记。Windows 使用当前用户的 DPAPI 封装本机配置下的定位地址和原完成链接，以 `opi-hub-focus:` 唤起 GUI 程序。程序读取默认浏览器关联，将 `--focus` 选择器和备用结果链接传给支持的 Chromium 浏览器，不枚举窗口、不使用远程调试。计划结果不走按会话选页的入口。

Windows 探测与发送共用应用身份和权限检查。通过 `Get-StartApps` 查找 Windows PowerShell 的已注册应用标识，不使用任意固定标识。脚本使用 UTF-16LE 编码的 `-EncodedCommand`，通知文字仍只通过 UTF-8 标准输入进入 XML 文本节点。读取权限时显式调用 `get_Setting()`，避免 PowerShell 属性访问隐藏 WinRT 异常。已注册的桌面应用在第一次发送前可能尚无通知设置，仅兼容 `ERROR_NOT_FOUND`（`0x80070490`），发送后再次检查权限且不再忽略该错误。其他错误及明确的禁用状态均报告失败，不修改系统设置。启动探测不发送通知，失败时不订阅中心。命令失败日志包含退出码和有界错误详情，不输出命令全文。Windows 无弹窗测试覆盖应用标识缺失、首次设置缺失、权限禁用和其他 WinRT 错误，实际弹窗仍需人工验收。

使用 `--windows-approvals` 或 `--linux-approvals` 启动的接收节点在订阅时另外声明审批能力。中心从管理快照发现新的命令审批、选择和确认。已绑定且声明 `approvalLinks` 的接收节点收到有界的预览、原交互定位和可直接提交的选项。超过预览范围时标明截断，但不取消投递或移除选项。旧接收节点仍按原规则接收能完整放进通知的单行命令审批。普通文本、密钥和编辑器交互不下发。中心在同一控制连接上接受回传，从该接收端已收到的通知查找原设备、会话和交互，并复用 `Nodes.respond`。点击不会提交任意审批目标或回答值。每个接收节点最多保留最近 100 个可回传的标识，断开控制连接后失效，不撤回系统通知。

Windows 通知按钮使用当前用户注册的 `opi-hub-approval:` URI。节点启动时通过 Windows PowerShell 生成并注册无控制台的 Windows GUI 程序。点击时由该程序直接将标识和决定写入本机命名管道，不再启动 Node.js 或命令解释器。Linux 使用 `notify-send --action` 回传已提供的 `allow` 或 `deny` 选项。点通知正文或“查看审批”只打开浏览器，由已登录的 Hub 页面定位待处理项。节点用本机配置的 Hub 地址构造链接，链接只含设备、会话和交互标识，不包含凭据或审批决定。Linux 通过 `xdg-open` 打开链接。按钮等待单独限制为最多八个子进程，不占用普通通知队列。节点断线时取消等待，不向新控制连接转交旧按钮。测试替代桌面动作，不自动显示弹窗。

## 新建会话与目录浏览

`/_hub/directories` 查询所选设备的原生 `directories` 接口，使用独立未选择会话的临时客户端，结果绑定设备连接标识。关闭弹窗、切换设备、断线和超时会取消读取并释放该客户端。此功能只列出已有目录，不使用本地浏览器文件选择器，也不创建目录。

`/_hub/sessions` 接收设备、绝对目录路径及创建标识。控制请求 `createSession` 只等待节点确认接收，HTTP 返回 202 并不表示初始化完成。节点的创建记录通过持续管理状态上报，因此弹窗关闭后仍可处理启动交互。

节点按创建标识去重，并限制每设备一个在途创建。创建器先查询并取得规范目录，再依次执行 `workspace` 和 `new`，检查最终会话 ID 与工作区定位阶段的 ID 不同。两个阶段的对话框均由创建器的独立客户端接收并交给集中交互，不借用原生页面的连接，不默认放行项目。最后一个回答的 HTTP 响应完成前不回收创建客户端。

创建完成后保留会话身份，管理层观察尚未进入原生目录的空白会话，使其立即可见。已进入运行目录的会话复用正常订阅。会话删除时，创建记录不再提供失效入口。仅管理订阅断线时保留同一托管进程的创建身份；真正重启后端会替换整组 SDK 订阅并清空旧内存状态。记录及去重状态不落盘，不能承诺跨后端或节点重启的创建幂等。

创建不自动重试，也不提供会话回滚。连接中断可能已经登记部分会话，错误记录保留已观察到的相关身份供用户检查。UI 完成后提供显式打开链接，避免异步创建被浏览器拦截弹窗。

## 计划任务与执行监控

计划定义与运行分离。`ScheduleStore` 将计划、任务描述、每次触发身份和状态写入 SQLite，`Scheduler` 负责到期扫描与状态核对。界面通过 `/_hub/schedules` 和 `/_hub/runs/<id>/...` 操作计划与运行，不直接驱动原生页面。

选择中心调度而非各节点自行计时，使启停、时区和触发去重集中在一处。节点只执行已分配的运行，中心停机时不自行触发新计划。一次性、每天和每周规则通过 Temporal 显式计算时区。日历规则的重复时刻只选第一次，不存在的周期时刻跳过，一次性不存在时刻拒绝保存。

间隔规则分为 `interval` 与 `dailyInterval`，包含 `start`、`end`、正整数 `minutes` 和 `timeZone`。前者使用本地日期时间定义单个连续窗口，后者使用每日时间定义窗口，结束早于开始时跨至次日，开始结束相同则拒绝。`interval.ts` 统一转换窗口边界、按真实经过分钟计算下一个槽位并判断窗口是否截止。开始包含、结束排除，槽位始终锚定窗口开始，不根据创建、恢复或任务结束时间漂移。每日窗口每次重新锚定，跨午夜时先检查前一天开启的窗口。

窗口边界有歧义时取第一次。固定范围的边界不存在则拒绝，日窗口的边界不存在则跳过整个窗口。间隔本身按实际分钟计算，夏令时回拨中的两个相同钟面时间可能分别触发，UTC 身份仍然不同，不属于重复派发。窗口内超过一个槽位时直接计算未来槽位，不遍历或补发已错过的每次运行。

计划库使用 WAL 和 `synchronous=FULL`。同目录的独立 SQLite 排他事务锁阻止两个中心同时持有调度权。领取到期计划时，在同一事务中推进下一次时间，并写入带唯一触发键的运行记录，提交后才发送 `startTask`。这样避免正常重启或重复扫描再次下发，不声称实现跨数据库与节点的恰好一次执行。响应丢失会标为未知，不自动重试。人工“立即执行”代表新运行，不是重试原运行。

每秒先核对节点状态，再扫描到期计划。每台设备最多一个未结束或待核对的计划运行，上次未结束时记录跳过，不排队。离线、未就绪或扫描延迟超过 30 秒时记录错过，不补跑。间隔窗口截止后即使仍在 30 秒宽限期内也不下发。固定范围最后一个槽位之后无下一次时自动停用，日窗口则推进到下一个窗口。窗口截止不向在途会话发送取消。“立即执行”始终是明确的手动操作，不受时间窗口限制，也不改变原定触发时间。中心启动时将原在途运行标为未知，只等待节点回报，停机期间错过的多次周期合并记录一次并推进到未来。移除设备同时停用相关计划，保留运行记录。

节点管理层在当前托管实例中按运行 ID 去重，保留所有未结束或未知任务及最近 100 个终态。相同 ID 不能改用于不同任务。节点和后端重启都会清空这部分身份，中心不会因此重发。中心数据库记录持续保留，页面仅展示全部未确认运行及最近 50 条，不把历史运行铺在会话首页。

`SessionPort` 复用目录校验、独立工作区定位、新建会话和交互提交。`AgentTask` 在确认得到全新、空闲且没有用户条目的专用会话后，发送一次自然语言 `prompt`，不允许直接的 Shell 或斜杠命令。计划可带可选的 `model: { provider, id }`，省略时保留原生新会话的默认模型。领取运行时保存模型选择，定时与手动下发使用同一选择。节点在发送提示词前执行原生 `model` 操作，只切换专用会话，不持久化设备默认模型。切换失败时不发送提示词，也不自动换模型。上下文、项目授权和工具审批仍由原生后端决定。审批继续通过现有集中交互返回，任务不借用人工页面的客户端身份。

模型列表复用已有目录客户端的会话快照与增量，只投影 `models` 中的提供商、标识和显示名称。列表随管理状态上报，经概览交给所选设备的模型下拉框，不读取提供商配置或凭据。断线清除旧列表，设备变化重置选择，同设备列表变化时保留已选但不可用的标识并明确标注，不静默退回默认。

执行订阅在节点本机接收快照和增量。`ExecutionState` 仅投影会话身份、用户条目数量、忙碌标记及助手停止原因，不缓存正文、思考或工具输出。无忙碌标记后按原生停止原因区分结束、提供商错误和取消，输出长度上限单独提示。“已结束”不是任务内容成功的保证。中心只接收任务身份、状态、会话入口、最终助手条目标识和错误摘要，完整输出留在原生会话。

结果卡片进入可见区域后，由浏览器通过现有认证 HTTP/WebSocket 代理建立独立、未选择会话的临时原生客户端，再按记录的文件或会话定位。`hub-preview=1` 标记使这类连接不参与用户查看或会话发现。记录校验会话身份，只提取记录所绑定条目中的助手文本，不用最后一条新回复替代丢失的旧回复。正文由本地打包的 `markdown-it` 渲染，关闭原始 HTML，只允许 HTTP、HTTPS 和邮件链接。外链带 `noopener noreferrer` 并在新标签打开，图片只渲染替代文字，不请求远程资源。表格对齐使用样式类，不放宽现有 CSP。复制始终使用原始 Markdown。

运行记录按 ID 保留 DOM 节点，进行中和待核对项在前，历史按浏览器本地的触发日期分组。正文默认折叠到几行，根据实际溢出决定是否显示展开按钮，代码块和表格可在正文内横向滚动。元数据详情和正文展开状态保留在页面内存，其他运行更新不重置当前阅读状态。

结果读取最多并发 3 个，20 秒未完成就释放连接，不自动重试。正文最多预览约 128K 字符，截断会提示。页面缓存绑定设备连接和托管实例，离开计划页取消在途读取，断线、管理订阅失效或退出登录清除缓存。回复正文不进入管理快照、概览、SQLite、localStorage 或 sessionStorage。旧数据库记录可缺少 `replyId`，界面明确提示不能定位，不回填或猜测正文。

超时包含初始化和等待审批，节点负责计时，所以中心断线不取消超时约束。取消或超时只对所属专用会话发送 `abort`，再同步状态确认空闲，不关闭整个后端。尚未获得专用会话身份时，不中止可能属于其他用户操作的工作区实例。无法确认停止、执行连接中断或节点退出时标为未知，阻塞同设备后续计划。

未知任务在节点重新回报时继续核对，不重新发送提示词。人工确认结束不会发送停止指令，节点仍知道任务在执行时会拒绝确认。节点已重启或设备已移除而无法复原运行时，只能由用户核对实际设备后确认，系统不能替用户证明孤立进程已经结束。

计划与运行数据库包含任务描述和错误摘要，需按敏感数据限制权限。正常停止中心后备份整个数据目录，不在运行中单独复制主数据库。运行记录不清理原生会话，暂停计划不停止当前运行，取消当前运行不暂停计划。

## 托管后端与生命周期

配置仅接受 `hub`、`token`、`command` 和可选 `cwd`、`notifications` 布尔值（默认开启，显式 `false` 关闭）。没有 `target`、外部模式、端口复用或已有进程接管。`command` 是可信本机程序及前置参数数组，使用 `spawn`、`shell: false`、`windowsHide: true`。固定追加 `--host 127.0.0.1 --port 0 --cwd ...`，仅接受有效的回环 HTTP 启动地址并检查 `/health`。

`ManagedBackend` 持有实际 ChildProcess 句柄、PID、退出信号、启动超时和有界 Unicode 日志。每次启动/重启递增实例代数。`NodeRuntime` 负责对应 SDK 订阅的原子替换，拒绝旧订阅回填新状态。中心连接生命周期与本机后端分离，断线重连不重启后端。

后端状态包括启动、运行、停止中、失败和已停止。启动失败会清理本次子进程并报告错误，异常退出不自动重启。已退出的父进程不会触发全局孤儿进程扫描。节点关闭会结束自己仍持有的进程树：POSIX 使用独立进程组，Windows 仅使用所属 PID 的 `taskkill /T`，必要时强制终止，不按名称或端口清理。

`/_hub/backend/restart` 在登录和同源校验后发送重启确认请求。确认同时绑定节点连接标识及实例代数，节点再次校验代数，防止旧确认重启新的工作实例。重启确认只表示命令接收，不表示启动成功，最终状态由后续报告提供。后端变化立即取消在途历史/目录读取，但不误取消引发该变化的重启确认。

节点正常停止或设备被撤销会中断托管任务。强杀节点或系统故障不保证回收子进程，本版不实现独立守护进程或 OS Job 管理，也不扫描接管残留进程。浏览器关闭、中心断线不结束后端。中心重启后登录会话失效，节点使用已有凭据自动连接。只保留原生已持久化的历史，不自动恢复任务或重放任何变更请求。

设备撤销和重复节点替换使用关闭码 4001，旧节点停止自动重连，避免争抢同一身份。中心关闭使用 1001，节点继续尝试重连。

转发失败不重发用户操作，因为无法根据网络结果判断本机是否已经执行。
