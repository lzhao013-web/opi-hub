# opi-hub

独立的 o-pi 多设备管理入口。首页显示设备状态、正在进行的会话和少量最近活动，通过“设备 → 工作区”浏览会话。历史只在明确加载或查询时读取，待处理交互仍跨设备集中展示。点击会话可打开对应的原生 o-pi 页面。

不修改 o-pi，不安装 o-pi 插件，不转发终端画面。会话执行、文件、模型凭据和本地审批策略保留在各设备上。

## 环境

- **Node.js >= 24**：运行中心和节点，直接执行 TypeScript。
- **Bun**：安装依赖和构建。运行脚本会显式启动 Node，不要用 `bun src/cli.ts` 替代。
- 被管理设备已运行 `opi-web`，或已启用 Desktop Web。

## 启动中心

```bash
bun install
bun run init
bun run hub
```

`init` 创建 `data/hub.json` 并显示随机初始密码。请保存在密码管理器中。也可以在初始化前通过环境变量 `OPI_HUB_PASSWORD` 指定至少 12 个字符的密码。已有数据不会被覆盖。

打开 `http://127.0.0.1:19200`，使用中心密码登录。

### 其他设备访问

指定实际访问地址和监听地址。例如，中心的局域网或 Tailscale IP 为 `100.100.1.2`：

```bash
bun run hub --host 0.0.0.0 --port 19200 --public-url http://100.100.1.2:19200
```

`--public-url` 是所有浏览器和节点使用的统一入口。可以使用 IP 或域名，不能包含子路径。服务校验 Host 和 Origin，访问地址必须与配置一致。

HTTP 仅用于本机或受保护的可信内网。应用层不会加密 HTTP 中的密码、凭据和会话。公网必须使用 HTTPS。

## 添加设备

1. 在管理界面点击“添加设备”，填写名称。
2. 下载节点配置 `node.json`。设备凭据仅在创建时显示。
3. 在目标设备安装本项目依赖，启动本机 o-pi Web：

   ```bash
   /path/to/opi-web --host 127.0.0.1 --port 19198 --cwd /path/to/project
   ```

   控制已有 Desktop 会话时，启用 Desktop 自身的 Web 访问。另开一个 `opi-web` 是独立后端，不能接管原来的 Desktop 或 TUI 运行实例。

4. 确认配置中的本机地址：

   ```json
   {
     "hub": "http://100.100.1.2:19200",
     "token": "管理界面生成的完整设备凭据",
     "target": "http://127.0.0.1:19198"
   }
   ```

   `target` 仅允许 `127.0.0.1`、`localhost` 或 `[::1]` 的 HTTP(S) 地址。不要公开本机免登录的 o-pi Web 端口。

5. 在本项目目录启动节点：

   ```bash
   bun run node --config /path/to/node.json
   ```

6. 中心显示“在线”后，点击“打开 o-pi”。

每个配置对应一个本机 Web 后端。可以用多个设备条目连接同一机器上的不同后端，不自动发现进程。

## 会话与集中交互

- “概览”显示设备状态、正在进行的会话，以及最多 5 个最近活动的空闲会话，不铺开全量历史。
- 左侧按设备展开工作区，选择工作区后浏览其会话。手机使用“设备与工作区”选择器。
- 工作区默认只显示已知运行实例。点击“加载历史会话”后才读取目标设备目录，并只展示当前工作区。已加载的历史只保留在页面内存，不随概览轮询刷新，可手动刷新或取消读取。
- “查找历史”需要输入关键词并明确查询，范围可选单台或全部在线设备。只匹配标题、设备名称和工作目录，不搜索聊天正文。
- 上游接口目前按后端返回目录，不能单独查询一个工作区。因此一次加载会读取所选设备的历史，再按工作区筛选。hub 不再主动请求、保存或同步所有设备的全量历史。上游自身的启动或原生页面刷新仍可能读取其默认目录，这部分不由 hub 控制。
- “进入会话”直接打开目标运行会话或历史文件，不会切换其他浏览器页面的选择。
- “待处理交互”汇总命令审批、选择、确认、文本输入、密钥输入和编辑器。命令审批保留工作目录、完整命令、目标范围、原因和原有选项。
- 回答由设备上的 o-pi 校验和消费。原界面已处理、取消或过期的交互不能再次消费。中心不新增放行规则，也不自动重试提交。
- 中心界面在前台每 2 秒拉取运行摘要和交互，不拉取历史。节点或本机订阅断线时清除旧摘要、旧交互和页面内历史缓存。重连后需手动重新加载历史。
- 文本回答请求体上限 1 MiB。输入草稿只保留在当前页面内存，不写入浏览器持久存储。

**发现范围**：原生全局目录不公开尚未提交消息的新建空白会话。经 hub 打开的页面会提供会话发现提示，因此这些页面的新建会话也能集中交互。仅在本机直接创建、既未进入原生目录也从未经过 hub 的空白会话无法自动发现。完整覆盖这类会话需要额外的后端接口或桥接扩展。节点进程重启也会失去对未索引会话的发现记录，需再次经 hub 打开原页面。中心短暂断线不会丢失仍在运行的节点订阅。

节点使用本机协议适配器订阅数据，只上报摘要和交互，不上报聊天快照或正文。管理订阅有独立客户端身份，不借用原生页面的连接。当前支持已验证的无 `kind` 帧二进制及带 `kind: frame` 的源码协议，未来上游变更可能需要更新适配器。

升级本项目后需重启中心和各节点，旧节点进程不会自动获得新功能。

节点需要保持运行。设备改 IP 后使用原凭据重连，不需要重新注册。连接中断时自动重连，中心重启后恢复设备连接。移除设备会撤销凭据并断开远程连接，不删除本机会话，也不主动停止 o-pi 任务。

## HTTPS

中心可以直接加载证书：

```bash
bun run hub --host 0.0.0.0 --port 19200 \
  --public-url https://hub.example.com:19200 \
  --cert /path/to/fullchain.pem --key /path/to/privkey.pem
```

证书需要被浏览器和节点的操作系统信任。IP 地址访问同样需要匹配该 IP 的证书。

也可以让反向代理提供 HTTPS，并把中心保持在回环地址：

```bash
bun run hub --public-url https://hub.example.com
```

反向代理需要保留外部 Host，并支持整个站点的 WebSocket Upgrade、流式响应和较大的附件请求体。不要只代理聊天事件路径，节点连接和每个独立传输通道也使用 WebSocket。

## 安全边界

- 当前版本是**单用户系统**，所有设备属于同一信任域。中心密码允许访问全部已注册设备。
- 中心能读取经它转发的会话和文件。审批命令、路径以及输入回答也会经过中心，管理状态只保存在内存中。HTTPS 是分段传输加密，不是设备与浏览器之间的端到端加密。
- 设备 GUI 与管理界面共享浏览器来源。只接入自己信任的 o-pi 后端，不能作为不可信用户或设备之间的隔离方案。
- 节点凭据仅允许连接所属设备，不能用作浏览器登录。中心只保存凭据散列。
- 登录 Cookie 使用 HttpOnly、SameSite=Strict，HTTPS 入口增加 Secure。登录会话保存在内存中，有效期 12 小时，中心重启后需要重新登录。
- 中心 Cookie、节点认证头不会传给本机 o-pi。
- 设备操作不会自动重试。连接在提交后中断时，请先检查会话状态，避免重复操作。
- `data/hub.json` 和 `node.json` 都是敏感文件，需限制读取权限并妥善备份。

## 构建与验证

```bash
bun run typecheck
bun run test
bunx playwright install chromium --only-shell
bun run test:browser
bun run build
```

构建后可分发 `dist/`，不需要在目标机器安装项目依赖，使用 Node 运行：

```bash
node dist/cli.js init
node dist/cli.js hub
node dist/cli.js node --config /path/to/node.json
```

真实 o-pi Web 的定向无头测试需要指定已构建二进制。测试使用临时工作区和配置，不读取用户模型凭据，不调用模型：

```bash
# Bash
OPI_WEB_BINARY=/path/to/opi-web bun run test:native
```

```powershell
$env:OPI_WEB_BINARY = 'F:/o-pi/dist/web/opi-web.exe'
bun run test:native
```

测试覆盖认证、设备注册和撤销、双设备隔离、HTTP/WebSocket 转发、附件请求体、流式文件、Range、中心重启及桌面/手机布局。真实二进制测试覆盖 GUI 加载、会话重命名、刷新恢复、文件预览、工作区浏览、按需历史、会话直达和集中确认闭环。测试中的 `echo` 仅在临时工作区执行，不调用模型。

## 当前范围

已提供会话聚合、原生会话直达、集中交互和设备管理。尚未实现聊天正文的跨设备搜索、自动启动或升级 o-pi、多用户权限、服务安装与开机自启。

原生 GUI 的根路径 API 通过同源 Referer 路由，入口注入一个 WebSocket 路径适配脚本。不要配置会删除同源 Referer 的代理规则。上游 GUI 改变资源路径或连接方式后，需要重新运行真实二进制测试。

模块和传输机制见[架构说明](docs/architecture.md)。
