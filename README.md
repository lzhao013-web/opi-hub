# opi-hub

独立的 o-pi 多设备管理入口。首页显示设备状态、正在进行的会话和少量最近活动，通过“设备 → 工作区”浏览会话。历史只在明确加载或查询时读取，待处理交互仍跨设备集中展示。点击会话可打开对应的原生 o-pi 页面。

仅提供托管模式：节点自动后台启动自己的 `opi-web`，不需要手动打开 o-pi，不连接既有 Desktop、TUI 或独立 Web 进程。不修改 o-pi，不安装插件，不转发终端画面。文件、模型凭据和审批策略保留在设备上。

## 环境

- **Node.js >= 24**：运行中心和节点，直接执行 TypeScript。
- **Bun**：安装依赖和构建。运行脚本会显式启动 Node，不要用 `bun src/cli.ts` 替代。
- 被管理设备已安装或构建 `opi-web`。无需提前运行，节点负责启动和退出。
- 节点应以实际使用者账号运行，继承该账号的环境和 `~/.pi` 配置，不自动切换账户或提权。

## 启动中心

```bash
bun install
bun run init
bun run hub
```

`init` 创建 `data/hub.json` 并显示随机初始密码。请保存在密码管理器中。也可以在初始化前通过环境变量 `OPI_HUB_PASSWORD` 指定至少 12 个字符的密码。已有数据不会被覆盖。

打开 `http://127.0.0.1:19200`，使用中心密码登录。

### 其他设备访问

指定实际访问地址和监听地址。例如，中心的局域网或 Tailscale IP 为 `100.100.1.2`：

```bash
bun run hub --host 0.0.0.0 --port 19200 --public-url http://100.100.1.2:19200
```

`--public-url` 是所有浏览器和节点使用的统一入口。可以使用 IP 或域名，不能包含子路径。服务校验 Host 和 Origin，访问地址必须与配置一致。

HTTP 仅用于本机或受保护的可信内网。应用层不会加密 HTTP 中的密码、凭据和会话。公网必须使用 HTTPS。

## 添加设备

1. 在管理界面点击“添加设备”，填写名称。
2. 下载节点配置 `node.json`。设备凭据仅在创建时显示。
3. 在目标设备安装本项目依赖，并准备 `opi-web` 程序，不要另行打开后端。
4. 将下载配置中的 `command` 改为该设备上的程序路径：

   ```json
   {
     "hub": "http://100.100.1.2:19200",
     "token": "管理界面生成的完整设备凭据",
     "command": ["F:/apps/opi-web.exe"],
     "cwd": "F:/projects"
   }
   ```

   Linux/macOS 可填写如 `["/opt/opi/opi-web"]`。`command` 是程序及可选前置参数的非空数组，不经过 Shell。推荐所有文件路径使用绝对路径。裸程序名从 PATH 查找，相对程序路径和 `cwd` 按启动节点时的当前目录解析。

   `cwd` 是后端初始目录，可省略，默认当前运行账号的主目录。之后可在任意有权限的已有目录新建会话。节点固定追加回环监听、自动端口和初始目录参数，不需要配置端口。配置仅在节点启动时读取，修改程序路径或初始目录后需重启节点。

   **旧配置不兼容**：删除 `target`，新增 `command`。保留原 `hub`、`token` 即可，旧字段不会被静默忽略。

5. 在本项目目录启动节点：

   ```bash
   bun run node --config /path/to/node.json
   ```

6. 节点会自动启动无窗口后端、分配回环端口并上报进程状态。中心显示“在线”后，点击“打开 o-pi”。

每个节点只管理自己启动的一份后端，多目录会话共用该后端，不扫描或接管外部进程。恢复历史前应先停止仍在写入该会话的手动进程，避免多进程并发写同一文件。同一设备凭据不要并行运行多个节点，后连接的节点会替换旧连接，旧节点随之退出并停止其托管任务。

## 托管后端生命周期

- 浏览器关闭或中心断线不结束后端。中心恢复后节点重连，不重启子进程。
- 正常停止节点、移除设备或替换设备连接，会结束该节点自己启动的后端和可归属的工具子进程，正在执行的任务会中断。
- 设备页显示后端状态、实际 PID 和最近约 4096 字符日志。启动失败或异常退出时节点仍在线，后端不会自动反复重启。
- “重启后端”需要明确确认，且绑定所确认的实例。实例变化后旧确认被拒绝。重启仅重新启动程序，不重发提示词、审批或工具操作。
- 退出先尝试终止并等待，必要时强制结束所属进程树。Windows 下控制台程序通常需要强制终止，不能保证正在进行的写入完成，应先等待任务结束再停节点。
- 只向所属 PID 或独立进程组发信号，不按进程名称、端口或全局进程列表清理。强制杀死节点、系统故障或后端崩溃时可能留下孤立进程，本版不做全局扫描接管或回收，需通过系统进程信息人工确认处理，不要批量终止同名进程。
- 重启只保留原生已写入磁盘的历史，内存中的会话、交互和创建记录不能自动恢复。纯 Shell 或尚未聊天的会话可能还未落盘。

当前不提供系统服务安装或开机自启，需要自行让节点常驻。启动命令必须是可信的、兼容 `opi-web` 参数和启动输出的程序。

## 远程新建会话

1. 点击“新建会话”。全局入口需选择设备，设备页会预选该设备，工作区页还会预填目录。
2. 输入目标设备上的绝对目录路径，或点击“浏览目录”选择。浏览器显示的是远程目录，可向上浏览，也可输入完整路径切换磁盘。
3. 点击“创建会话”。服务确认接收后关闭弹窗，进度显示在“会话创建”中。
4. 如需项目信任或启动确认，进入“消息中心 → 待处理”回答。显示“会话已就绪”后点击“打开会话”进入原生页面，不会自动弹出窗口。

设备节点必须在线，托管后端需已成功启动。目录需要已存在且允许后端进程账号读取，不会自动创建文件夹或提权。一个后端可在不同目录托管多个会话，不需要每个项目启动一份后端。

新建使用独立客户端，先定位工作区再明确执行原生新建操作，不把恢复已有会话当作新建，也不切换其他页面。首次使用某个目录时原生流程可能先初始化一个工作区会话，再建立最终的新会话，期间仍按原生策略询问信任。

每台设备同一时间只创建一个会话，其他设备不受影响。相同创建标识只执行一次，不能改用于另一个目录。幂等记录仅保留在当前托管后端运行期，后端或节点重启后不保留去重状态。关闭弹窗、刷新页面或丢失确认响应，都不等于撤销已经提交的创建。结果不明时请先检查创建记录和相关会话，不要直接发起新请求重试。

未落盘空白会话和创建记录由节点内存跟踪。节点重启后需从原生页面重新发现，后端重启可能丢失未落盘会话。已创建会话被删除后，旧创建标识不会重新创建它。

## 计划任务

进入“计划任务 → 新建计划”，选择设备，填写已有绝对目录和自然语言任务。支持一次性预约、每天、每周、日期范围内循环和每日时段内循环，也可从工作区的“预约任务”预填设备与目录。

- 时间按计划中的显式时区计算，默认填写浏览器时区，例如 `Asia/Shanghai`。一次性、每天和每周规则在本地时刻重复时只取第一次。不存在的一次性预约时刻会被拒绝，日历重复规则跳过不存在的时刻。
- “日期范围内循环”填写开始与结束日期时间、间隔分钟数，在这一个连续窗口内触发，到期自动停用。“每日时段内循环”填写开始与结束时间，每天重新开启窗口。结束早于开始表示跨至次日，例如 23:00–次日 01:00，开始和结束不能相同。
- 间隔是至少 1 分钟的整数，以各自窗口开始为基准，不从创建或上次完成时间重新计时。包含开始、不包含结束。晚创建或重新启用只选择未来槽位，窗口结束后不再自动触发，但不停止已开始的运行。确认后“立即执行”不受窗口限制，也不改变下一次预约。
- 间隔按实际经过的分钟计算。夏令时回拨可能在两次不同触发中出现相同的本地钟面时间，但间隔不变。窗口边界有歧义时取第一次，边界不存在时拒绝日期范围或跳过那次每日窗口，不平移边界。
- “任务模型”默认沿用设备默认配置，也可从所选设备的可用模型中指定。模型选择随计划保存，计划和运行记录均显示所选模型。切换设备会清除原设备的选择，旧计划保持原有默认行为。
- 每次执行新建专用会话，不续写人工会话。指定模型仅应用于该专用会话，不修改设备默认模型。指定模型不可用时运行失败，不发送任务或自动换模型。仍执行项目授权与工具审批，需要回答时进入“消息中心 → 待处理”，不会自动放行。
- 最长运行时间默认 30 分钟，可设为 1–180 分钟，包含会话初始化和等待审批。每台设备最多一个未结束的计划运行，人工会话仍可独立运行。上次未结束或结果待核对时，本次记录为跳过，不排队。
- 中心需保持运行。设备离线、后端未就绪或中心错过触发时刻时，只记录原因，不唤醒设备、不自动补跑。正常扫描允许最多 30 秒延迟。中心停机期间的多次错过合并为一条记录，然后推进到未来时间。
- 支持暂停、启用、确认后立即执行和删除计划。暂停不停止当前运行，取消某次运行也不暂停后续计划。修改任务需停用旧计划后新建。删除保留执行记录，尚有未结束或待核对运行时不能删除。
- 取消或超时会尝试停止对应的专用会话，不关闭整个后端。停止未确认、节点重启或执行连接中断时标为“待核对”，阻止该设备的后续计划。节点回报仍在执行时恢复监控，不重新发送任务。
- “确认已结束”仅在人工核对原任务确实结束后使用。此操作不发送停止指令，也不重试任务。设备尚在注册列表时，节点需在线就绪才能确认。
- 每次触发先持久化记录，再向节点下发。中心重启只恢复监控，不重新下发已记录的运行。该机制不保证任务恰好执行一次，结果不确定时需人工检查。
- “已结束”表示 SDK 执行结束，不代表任务内容已验证成功。提供商错误会单独报告，可通过“查看会话”检查原始结果。页面展示全部未结束或待核对运行，以及最近 50 条记录。

计划只接受自然语言任务，不接受以 `!` 或 `/` 开头的直接命令。自然语言任务仍可能调用 o-pi 工具执行命令，沿用设备原有权限与审批规则。

计划、任务描述、运行身份、状态和错误摘要保存到中心的 `data/schedules.sqlite`。SQLite 写入期间还会产生 `-wal`、`-shm` 文件，同目录的 `schedule-lock.sqlite` 用于阻止两个中心同时调度同一份数据。运行记录不保存助手正文、思考或工具输出，完整结果仍在设备上的原生会话中。节点只在内存保留任务去重和监控状态，重启后不能自动接续执行。

保存或手动下发的响应丢失时，先检查计划和运行列表，不要直接重复提交。第一版不提供任意 Cron、工作流、设备唤醒或自动任务重试。

### 在线查看任务结果

运行记录优先显示进行中和待核对项，历史按触发日期分组。已结束记录默认预览几行结果，可展开全文。完整目录、模型标识和触发方式收在“详情”中，异常说明仍直接展示。展开和详情状态不会因轮询或新增其他运行而重置。

已结束记录进入可见区域时，会直接从在线设备读取本次执行的最终文本回复，无需打开原生会话。正文支持 Markdown 标题、列表、引用、表格和代码块。复制得到原始 Markdown，不展示思考、工具调用或工具输出。原始 HTML 按文本显示，只允许 HTTP、HTTPS 和邮件链接，外链在新标签打开。图片仅显示替代文字，不自动请求外部资源。

中心只保存最终回复的条目标识，不保存正文。读取使用独立原生客户端，不切换已有页面。回复绑定本次运行的条目，后续人工续聊不会替换原结果。正文只留在当前页面内存，不写入浏览器持久存储。离开计划任务页会取消在途读取，设备断线或后端变化会清除缓存。重新读取需要节点在线，旧版本运行记录没有回复标识时仍需查看原会话。

单次预览最多展示约 128K 字符，超长内容会明确提示截断。读取失败不会自动反复重试，可以点击“重新读取回复”。

## 会话与集中交互

- “概览”显示设备状态、正在进行的会话，以及最多 5 个最近活动的空闲会话，不铺开全量历史。
- 左侧按设备展开工作区，选择工作区后浏览其会话。手机使用“设备与工作区”选择器。
- 工作区默认只显示已知运行实例。点击“加载历史会话”后才读取目标设备目录，并只展示当前工作区。已加载的历史只保留在页面内存，不随概览轮询刷新，可手动刷新或取消读取。
- “查找历史”需要输入关键词并明确查询，范围可选单台或全部在线设备。只匹配标题、设备名称和工作目录，不搜索聊天正文。
- 上游接口目前按后端返回目录，不能单独查询一个工作区。因此一次加载会读取所选设备的历史，再按工作区筛选。hub 不再主动请求、保存或同步所有设备的全量历史。上游自身的启动或原生页面刷新仍可能读取其默认目录，这部分不由 hub 控制。
- “进入会话”直接打开目标运行会话或历史文件，不会切换其他浏览器页面的选择。
- “消息中心 → 待处理”汇总命令审批、选择、确认、文本输入、密钥输入和编辑器。命令审批保留工作目录、完整命令、目标范围、原因和原有选项。
- 回答由设备上的 o-pi 校验和消费。原界面已处理、取消或过期的交互不能再次消费。中心不新增放行规则，也不自动重试提交。
- 中心界面在前台每 2 秒拉取运行摘要和交互，不拉取历史。节点或本机订阅断线时清除旧摘要、旧交互和页面内历史缓存。重连后需手动重新加载历史。
- 文本回答请求体上限 1 MiB。输入草稿只保留在当前页面内存，不写入浏览器持久存储。

### 消息中心与完成提醒

“消息中心”统一入口，分为“待处理”和“通知”。待处理项有独立计数，进入时优先展示。通知已读不会消费审批，审批仍须由 o-pi 实际校验和处理。

- 普通会话本轮执行完成及计划任务完成都会汇总为通知。计划通知可直接定位到运行结果卡片，普通通知可打开原生会话。
- 节点从执行元数据确认完成，不依赖原生系统通知，也不把断线、取消、模型错误或单独执行 Shell 命令当作完成。仅同步实际观察到的执行，不补扫历史完成事件。
- 对应会话正在当前浏览器的前台页面查看时，不重复弹出提醒，但仍保留通知记录。后台标签页和正在查看其他会话不抑制提醒。查看状态只识别经 Hub 打开的页面，不识别绕过 Hub 的本机页面。
- 浏览器通过认证事件流接收通知。选择“此浏览器”时，Hub 页面可在后台，但全部关闭后不推送；系统通知需授权，并使用支持通知的浏览器及 HTTPS 或 localhost。也可选择已授权的执行节点发送本机系统通知，不受浏览器安全上下文限制，关闭网页后仍可接收。站内完成记录不受通知渠道和权限影响。
- 同一浏览器的多个 Hub 标签页只投递一次提醒。通知不携带模型回复正文，首次打开页面和中心首次导入的旧通知不会集中补弹。
- 节点和中心各只在内存保留最近 100 条通知。设备离线不撤销已发生的通知。中心重启会重置已读状态，仍在运行的节点可重新上报其最近通知，但不补弹历史提醒。节点或后端重启后不恢复其旧通知记录。

#### 节点系统通知（可选）

执行节点可以兼任接收端，接收中心汇总的各设备完成摘要，在节点所在机器弹出系统通知，不会把弹窗转发到另一台没有接收节点的设备。

1. 节点默认尝试启用系统通知，无需添加配置；若要关闭，在本机节点配置中设置 `"notifications": false`。仍需系统通知入口可用及网页显式授权，默认开启不代表自动接收全部设备的摘要。先更新中心再更新接收节点；配置只在节点启动时读取，先等待任务结束再重启节点，避免中断其托管后端。
2. 在需要关联的浏览器打开“消息中心 → 通知”，将“系统通知接收端”从“此浏览器”改为该机器的节点。此操作授予节点读取各设备完成摘要的权限，但不能修改节点本机开关或启动命令。
3. 页面显示节点已订阅后即可使用。节点与中心保持连接即可接收，所有 Hub 页面关闭后仍有效。不依赖 Tailscale、Cloudflare Tunnel 或浏览器系统通知权限；公网链路仍应使用 HTTPS。

支持的本机入口：Linux 桌面的 `notify-send`（需图形会话和用户 D-Bus）、macOS 已登录图形会话的 `osascript`、Windows 交互式桌面的 PowerShell/WinRT，以及安装 Termux:API 和 `termux-notification` 的 Android Termux。工具须能从节点环境中找到，并具备系统通知权限；无桌面环境的节点不订阅，通知仍受系统勿扰策略限制。系统显示的发送应用名称由平台决定。

绑定保存在中心的 `hub.json`，每个浏览器配置只绑定一个节点，每个节点同时关联一个浏览器配置。同源同配置的多个标签页共享接收标识，中心先向已订阅节点认领投递，再发布浏览器事件，避免两路重复弹出。经 Hub 打开的原生页面也会续期查询节点通知状态，关闭 Hub 页面后仍避免重复的原生弹窗。不同浏览器配置或不同来源地址需要分别考虑绑定，不能按 IP 自动识别“同一台机器”。

切回“此浏览器”会撤销当前绑定；节点离线、本机显式关闭通知或工具不可用时，新事件回退浏览器提醒（仍需满足浏览器条件）。订阅成功不等于操作系统一定显示弹窗；通知是尽力投递，发送失败或队列溢出会记到节点日志，不自动重试，也不会重发任何任务。断线重连只恢复完成记录，不集中补弹离线事件；节点本机去重保留最近 100 个标识，发送队列最多 32 条。只有来源设备名、会话标题和完成事实会下发到接收节点，不包含聊天正文、文件路径或浏览器 Cookie。

**发现范围**：原生全局目录不公开尚未提交消息的新建空白会话。经 hub 打开的页面会提供会话发现提示，因此这些页面的新建会话也能集中交互。仅在本机直接创建、既未进入原生目录也从未经过 hub 的空白会话无法自动发现。完整覆盖这类会话需要额外的后端接口或桥接扩展。后端或节点重启会丢失未索引会话的内存身份，仅已保存的历史可以重新打开。中心短暂断线不会丢失仍在运行的节点订阅。

节点使用本机协议适配器订阅数据，只上报摘要和交互，不上报聊天快照或正文。管理订阅有独立客户端身份，不借用原生页面的连接。当前支持已验证的无 `kind` 帧二进制及带 `kind: frame` 的源码协议，未来上游变更可能需要更新适配器。

升级本项目后需重启中心和各节点，旧节点进程不会自动获得新功能。

节点需要保持运行。设备改 IP 后使用原凭据重连，不需要重新注册。连接中断时自动重连，中心重启后恢复设备连接。移除设备会撤销凭据并结束其托管后端，不删除已保存的历史，但会中断托管任务。

## HTTPS

中心可以直接加载证书：

```bash
bun run hub --host 0.0.0.0 --port 19200 \
  --public-url https://hub.example.com:19200 \
  --cert /path/to/fullchain.pem --key /path/to/privkey.pem
```

证书需要被浏览器和节点的操作系统信任。IP 地址访问同样需要匹配该 IP 的证书。

也可以让反向代理提供 HTTPS，并把中心保持在回环地址：

```bash
bun run hub --public-url https://hub.example.com
```

反向代理需要保留外部 Host，并支持整个站点的 WebSocket Upgrade、流式响应和较大的附件请求体。不要只代理聊天事件路径，节点连接和每个独立传输通道也使用 WebSocket。

原生操作接口可能等待完整推理或人工审批后才返回 HTTP 响应头。hub 不对这类长操作设置固定的响应头期限，普通资源仍保留 30 秒期限。反向代理的上游等待期限也需覆盖任务和审批等待，例如配置相应的 `proxy_read_timeout`。聊天 WebSocket 有活动，不会自动延长另一个 HTTP 请求的期限。

出现超时或连接中断时，先检查原会话是否仍在运行，不要重复发送。关闭等待连接不代表任务已停止，需要停止时使用会话中的停止操作。

## 安全边界

- 当前版本是**单用户系统**，所有设备属于同一信任域。中心密码允许访问全部已注册设备。
- 中心能读取经它转发的会话和文件。审批命令、路径以及输入回答也会经过中心。会话摘要、交互、完成通知与后端日志只保存在内存，任务回复正文仅按需转发到浏览器，计划定义、任务描述、运行状态和错误摘要另存 SQLite。HTTPS 是分段传输加密，不是设备与浏览器之间的端到端加密。
- 设备 GUI 与管理界面共享浏览器来源。只运行自己信任的后端程序，不能作为不可信用户或设备之间的隔离方案。后端日志可能包含敏感内容，只在已登录界面展示，不持久保存。
- 节点凭据仅允许连接所属设备，不能用作浏览器登录或访问浏览器 SSE 接口。节点接收跨设备完成摘要必须同时满足本机开启和已登录浏览器的显式授权；绑定可随时撤销。中心只保存凭据散列。
- 登录 Cookie 使用 HttpOnly、SameSite=Strict，HTTPS 入口增加 Secure。登录会话保存在内存中，有效期 12 小时，中心重启后需要重新登录。
- 中心 Cookie、节点认证头不会传给本机 o-pi。
- 设备操作不会自动重试。连接在提交后中断时，请先检查会话状态，避免重复操作。
- `data/` 和 `node.json` 都是敏感数据，需限制读取权限并妥善备份。任务描述和错误摘要也可能包含秘密。备份时先正常停止中心，再复制整个数据目录，不要运行中只复制 SQLite 主文件。

## 构建与验证

```bash
bun run typecheck
bun run test
bunx playwright install chromium --only-shell
bun run test:browser
bun run build
```

安装依赖时会自动准备 Markdown 浏览器模块，构建时也会重新准备并打包到 `dist/web/`，无需访问 CDN。若安装时跳过了生命周期脚本，先运行 `node scripts/prepare-web.ts`。

构建后可分发 `dist/`，不需要在目标机器安装项目依赖，使用 Node 运行：

```bash
node dist/cli.js init
node dist/cli.js hub
node dist/cli.js node --config /path/to/node.json
```

真实 o-pi Web 的定向无头测试需要指定已构建二进制。测试使用临时工作区和配置，不读取用户模型凭据，不调用模型：

```bash
# Bash
OPI_WEB_BINARY=/path/to/opi-web bun run test:native -- tests/native/schedules.spec.ts
```

```powershell
$env:OPI_WEB_BINARY = 'F:/o-pi/dist/web/opi-web.exe'
bun run test:native -- tests/native/schedules.spec.ts
```

测试覆盖认证、设备注册和撤销、双设备隔离、HTTP/WebSocket 转发、附件请求体、流式文件、Range、中心重启及桌面/手机布局。计划任务另覆盖时区、夏令时、间隔锚点、跨午夜、窗口截止、持久化与去重、离线错过、不重入、集中审批、取消和超时。定向界面测试使用 `bun run test:browser -- tests/browser/schedules.spec.ts tests/browser/interval.spec.ts`。

真实二进制由节点自动托管，可按需选择原生测试文件验证 GUI 加载、远程创建、集中交互或后端重启。`tests/native/timeout.spec.ts` 会实际保持审批超过 30 秒，再确认并验证响应正常返回。预约测试使用本机模拟模型，真实 SDK 创建会话、处理项目授权并执行推理流程，不读取用户模型凭据，不访问外部模型。测试中的 `echo` 仅在临时工作区执行。

## 当前范围

已提供会话聚合、远程目录浏览、新建会话、原生会话直达、集中交互、设备管理和计划任务。尚未实现聊天正文的跨设备搜索、自动安装或升级 o-pi、多用户权限、服务安装与开机自启。不支持外部后端模式。

原生 GUI 的根路径 API 通过同源 Referer 路由，入口注入一个 WebSocket 路径适配脚本。不要配置会删除同源 Referer 的代理规则。上游 GUI 改变资源路径或连接方式后，需要重新运行真实二进制测试。

模块和传输机制见[架构说明](docs/architecture.md)。
